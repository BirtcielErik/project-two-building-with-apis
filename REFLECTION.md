# Question 1

I chose the Open Library API because it was the most straightforward to set up (no key or account required) and the endpoints meshed very easily into the application that I was planning on building. There is a request limit of either 1 or 3 requests per second (depending upon setup), but I felt that for a project of this scope that those limits were acceptable. The other alternative I was considering was the Google Books API. Ultimately I decided against this choice because of the additional set up required to gain access to the API. Google requires an API key which can only be generated through a Google Cloud account. Creating the account and requesting the key are both free - the agent's research did not specify this, but I was able to track down the answer at `https://cloud.google.com/api-keys/pricing`. One thing that neither I or the agent could find from a primary source was the request limit for the Google Books API. Also, my understanding of the Google Books documentation is that every search request is limited to a response of a maximum of 40 books - if you want to see more results then you have to send a separate request. While probably not a big deal for the scope of my app, it still played a role in my decision.

# Question 2

One of the things I chose to prototype was the UI of the "My Shelf" page, which is the home page of a logged-in user. I chose to prototype this because it holds the main UI experience for the entire application and I wanted to make sure I picked the most visually appealing and user friendly option. I ended up choosing a list style display with a sidebar that contains all of the filter options, with a search bar and order drop down bar at the top. The second option was a catalog style layout where each book was displayed in a card where the cover art predominated and the only other information displayed for each book was the title, author, and rating. The third option was a table with columns for title, author, status, rating, date finished, date added, and notes, with cover art for each book displayed a thumbnail next to the title. In the end, I chose my option because it combined the best features of the other two options. The cover art for each book was bigger than a thumbnail, so it was more visually appealing, but there was still room on each book's row to list richer detail. I also took a "Currently Reading" ribbon from the second option and added it to the top of the screen above my list. This decision appears on the "My Shelf" page, which is the landing page for a logged in user.

# Question 4

The "My Shelf" page browses records saved into our app's database. The main logic of search, Q objects, filters, and sorting live in `shelf/filters.py`. All of these are implemented using Django's built in filter set - the agent recommended utilizing the pre-built filters instead of essentially re-implementing them from scratch. Search is at line 85 as well as the `search()` method at line 108. The only Q objects appear in line 110. The different filters are in lines 86-92 as well as the `filter_rated()` method at line 112. Ordering comes at line 93. Pagination is located at `shelf/views.py:69-70`. Search utilizes the `search()` method mentioned above, which uses the Q objects to search the shelf by title OR author. The `search()` method is necessary because Django's filter set joins multiple arguments with AND by default, so a custom method is required to implement the OR via Q objects. The `status` filter checks against the status field in the `ShelfEntry` model (tbr, dnf, etc.). The `min_rating` filter lets you filter by star ratings from 1 star and above, up to 5 stars and above. The `rated` filter lets you filter books by whether they have a rating yet or not. Ordering works on all of the different options listed in `shelf/filters.py:28-40`. Ordering uses a custom class located in `shelf/filters.py:48`. This class was necessary because I wanted items with null values to appear at the bottom of the list when ordering by any field that can be null. In certain ordering schemes, null values will appear at the top by default. Once all filters and ordering have been completed, the pagination occurs using `PAGE_SIZE` located in `shelf/filters.py:15` as the number of entries to show on a single page. On a seeded account with 18 books on the shelf, I typed "the" into the search box. The browser control in `shelf/templates/my_shelf.html:52` sends the GET request to the `my_shelf` view (`shelf/views.py:47`) with a q parameter of "the". The view then passes the request on to `ShelfEntryFilter` (`shelf/filters.py:77`) which then utilizes the `search()` method. This method uses Q objects to search for "the" in either the author OR the title. The results are then paginated and sent to the partial template `shelf/templates/partials/shelf_results.html` to be displayed.
